# 第一章 概述

为规范应用系统建设过程中的安全设计，确保系统满足《网络安全等级保护基本要求》（GB/T 22239-2019）的相关规定，特编制本文档，明确系统在规划与设计阶段需要落实的各项安全要求。

本文档涵盖身份鉴别、访问控制、安全审计、入侵防范、恶意代码防范、数据完整性、数据保密性、备份和恢复、剩余信息保护、个人信息保护等十大安全控制领域，为系统设计人员提供全面的安全设计参考。

# 第二章 身份鉴别

身份鉴别是系统安全的第一道防线，要求确保每个登录用户都有唯一的身份标识，并采用可靠的鉴别机制验证用户身份。

## 2.1 用户身份标识与鉴别

### 安全要求

- 应对登录的用户进行身份标识和鉴别，身份标识具有唯一性
- 身份鉴别信息具有复杂度要求并定期更换

### 设计要点

| **设计项**   | **具体要求**                                             | **实现方式**                                   |
| ------------ | -------------------------------------------------------- | ---------------------------------------------- |
| 用户身份标识 | 用户名唯一<br>支持工号/学号等唯一标识                    | 数据库唯一约束<br>注册时校验重复               |
| 口令复杂度   | 长度≥8位<br>包含大小写字母+数字+特殊字符<br>定期90天更换 | 正则表达式校验<br>密码策略配置<br>到期提醒机制 |
| 鉴别机制     | 支持多种鉴别方式<br>口令+短信验证码<br>支持生物识别      | 双因素认证(2FA)<br>动态令牌<br>指纹/人脸       |

## 2.2 登录失败处理

### 安全要求

- 应具有登录失败处理功能，配置并启用结束会话、限制非法登录次数和登录连接超时自动退出等措施

### 设计要点

| **设计项**   | **具体要求**                                        | **实现方式**                                   |
| ------------ | --------------------------------------------------- | ---------------------------------------------- |
| 登录失败锁定 | 连续失败5次锁定<br>锁定时间30分钟<br>支持管理员解锁 | 计数器+定时器<br>账户锁定表<br>解锁接口        |
| 会话超时     | 空闲超时自动退出<br>默认30分钟<br>可配置            | Session超时机制<br>心跳检测<br>前端倒计时提醒  |
| 并发控制     | 限制同一账户多点登录<br>支持踢出功能                | Session唯一性校验<br>Token机制<br>登录日志记录 |

## 2.3 远程管理安全

### 安全要求

- 当进行远程管理时，应采取必要措施防止鉴别信息在网络传输过程中被窃听

### 设计要点

- 远程管理必须采用加密传输协议（SSH、HTTPS、VPN等）
- 禁止通过明文协议（Telnet、HTTP、FTP）传输鉴别信息
- 采用TLS 1.2及以上版本加密通信
- 部署VPN网关，实现远程安全接入

## 2.4 双因素鉴别

### 安全要求

- 应采用口令、密码技术、生物技术等两种或两种以上组合的鉴别技术对用户进行身份鉴别
- 其中一种鉴别技术至少应使用密码技术来实现

### 设计要点

| **组合方式** | **第一因素**      | **第二因素**        |
| ------------ | ----------------- | ------------------- |
| 方案一       | 静态口令          | 短信验证码/动态令牌 |
| 方案二       | 数字证书(USB Key) | PIN码               |
| 方案三       | 静态口令          | 指纹/人脸识别       |

# 第三章 访问控制

访问控制确保只有经过授权的用户才能访问系统资源，遵循最小权限原则，防止越权访问。

## 3.1 账户和权限分配

### 安全要求

- 应对登录的用户分配账户和权限
- 应及时删除或停用多余的、过期的账户，避免共享账户的存在

### 设计要点

| **设计项** | **具体要求**                                   | **实现方式**                                     |
| ---------- | ---------------------------------------------- | ------------------------------------------------ |
| 账户管理   | 一人一账户<br>禁止共享账户<br>账户生命周期管理 | 账户申请审批流程<br>定期账户清理<br>离职自动禁用 |
| 权限分配   | 基于角色的访问控制<br>最小权限原则<br>权限分离 | RBAC模型<br>角色-权限映射<br>权限审批流程        |

## 3.2 默认账户管理

### 安全要求

- 应重命名或删除默认账户，修改默认账户的默认口令

### 设计要点

- 系统初始化时强制修改默认账户口令
- 重命名默认管理员账户（如admin→自定义名称）
- 禁用不必要的默认访客账户
- 建立默认账户清单，定期检查清理

## 3.3 权限分离

### 安全要求

- 应授予管理用户所需的最小权限，实现管理用户的权限分离
- 应由授权主体配置访问控制策略
- 访问控制的粒度应达到主体为用户级或进程级，客体为文件、数据库表级

### 设计要点

| **角色**   | **职责**     | **权限范围**       |
| ---------- | ------------ | ------------------ |
| 系统管理员 | 系统配置维护 | 系统级参数配置     |
| 安全管理员 | 安全策略配置 | 访问控制、审计配置 |
| 审计管理员 | 日志审计分析 | 只读访问审计日志   |
| 业务管理员 | 业务数据管理 | 指定业务功能操作   |

## 3.4 安全标记

### 安全要求

- 应对重要主体和客体设置安全标记，并控制主体对有安全标记信息资源的访问

### 设计要点

- 对系统资源进行分级分类（公开、内部、秘密、机密）
- 为用户分配相应的安全级别和访问许可
- 实现基于安全标记的强制访问控制（MAC）

# 第四章 安全审计

安全审计是系统安全体系的重要组成部分，通过记录、分析用户行为和安全事件，及时发现安全威胁，并为安全事件调查提供依据。

## 4.1 审计功能启用

### 安全要求

- 应启用安全审计功能，审计覆盖到每个用户
- 对重要的用户行为和重要安全事件进行审计

### 设计要点

| **审计事件类型** | **审计内容**                         | **实现方式**                  |
| ---------------- | ------------------------------------ | ----------------------------- |
| 登录审计         | 登录/登出<br>登录失败<br>密码修改    | 认证模块拦截器<br>AOP切面记录 |
| 操作审计         | 数据增删改查<br>权限变更<br>配置修改 | 操作日志注解<br>数据库触发器  |
| 安全审计         | 越权尝试<br>异常访问<br>攻击行为     | WAF日志<br>IDS/IPS告警        |

## 4.2 审计记录内容

### 安全要求

- 审计记录应包括事件的日期和时间、用户、事件类型、事件是否成功及其他与审计相关的信息

### 设计要点

| **字段名**    | **说明**     | **示例**            |
| ------------- | ------------ | ------------------- |
| event\_time   | 事件发生时间 | 2026-08-20 14:30:25 |
| user\_id      | 操作用户标识 | zhangsan            |
| event\_type   | 事件类型     | LOGIN\_SUCCESS      |
| event\_result | 事件结果     | SUCCESS/FAIL        |
| source\_ip    | 来源IP地址   | 192.168.1.100       |
| resource      | 访问资源     | /api/user/list      |
| detail        | 详细描述     | 查询用户列表        |

## 4.3 审计记录保护

### 安全要求

- 应对审计记录进行保护，定期备份，避免受到未预期的删除、修改或覆盖等
- 应对审计进程进行保护，防止未经授权的中断

### 设计要点

- 审计日志存储在独立的安全日志服务器，与业务系统分离
- 采用WORM（一次写入多次读取）存储介质或防篡改机制
- 定期备份审计记录（建议每日增量、每周全量）
- 审计记录保存期限不少于6个月（三级系统要求12个月）
- 审计进程采用守护进程监控，异常退出自动重启
- 仅审计管理员可查看审计记录，系统管理员无权修改或删除

# 第五章 入侵防范

入侵防范要求系统能够主动发现并阻断各类网络攻击和入侵行为，保障系统运行安全。

## 5.1 最小化安装与端口管理

### 安全要求

- 应遵循最小安装的原则，仅安装需要的组件和应用程序
- 应关闭不需要的系统服务、默认共享和高危端口

### 设计要点

| **设计项** | **具体要求**                                     | **实现方式**                               |
| ---------- | ------------------------------------------------ | ------------------------------------------ |
| 最小化安装 | 仅安装必要组件<br>移除示例程序<br>禁用不必要功能 | 定制化安装包<br>组件清单管理               |
| 服务管理   | 关闭非必要服务<br>禁用默认共享<br>关闭高危端口   | 服务清单审核<br>端口扫描验证<br>防火墙策略 |
| 终端接入   | 限制管理终端<br>IP白名单<br>MAC绑定              | 网络访问控制<br>终端准入系统               |

## 5.2 输入验证

### 安全要求

- 应提供数据有效性检验功能，保证通过人机接口输入或通过通信接口输入的内容符合系统设定要求

### 设计要点

- 前后端双重验证：前端格式校验 + 后端业务规则校验
- 防范SQL注入：使用参数化查询/预编译语句
- 防范XSS攻击：输入过滤 + 输出编码 + CSP策略
- 防范CSRF攻击：Token验证 + Referer检查
- 文件上传限制：类型白名单 + 大小限制 + 内容检测

## 5.3 漏洞管理

### 安全要求

- 应能发现可能存在的已知漏洞，并在经过充分测试评估后，及时修补漏洞

### 设计要点

- 建立漏洞管理制度，明确漏洞发现、评估、修复流程
- 定期进行漏洞扫描（建议每季度至少一次）
- 关注CVE/CNNVD等漏洞库，及时获取安全公告
- 高危漏洞应在72小时内完成修复
- 修复前应进行充分测试，评估补丁兼容性

## 5.4 入侵检测与报警

### 安全要求

- 应能够检测到对重要节点的入侵行为，并在发生严重入侵事件时提供报警

### 设计要点

- 部署入侵检测系统（IDS/IPS）监测网络流量
- 部署Web应用防火墙（WAF）防护应用层攻击
- 部署主机入侵检测系统（HIDS）监测主机行为
- 建立安全事件告警机制（短信、邮件、钉钉等）
- 制定应急预案，明确入侵事件处置流程

# 第六章 恶意代码防范

恶意代码防范要求系统能够及时识别并阻断病毒、木马、蠕虫等恶意代码的攻击。

## 6.1 恶意代码防护

### 安全要求

- 应采用免受恶意代码攻击的技术措施或主动免疫可信验证机制及时识别入侵和病毒行为，并将其有效阻断

### 设计要点

| **防护层面** | **防护措施**                          | **技术实现**                             |
| ------------ | ------------------------------------- | ---------------------------------------- |
| 网络层       | 网络防病毒<br>恶意URL过滤<br>邮件过滤 | 防病毒网关<br>URL分类库<br>邮件网关      |
| 主机层       | 终端防病毒<br>实时监控<br>定期扫描    | EDR系统<br>杀毒软件<br>白名单机制        |
| 应用层       | 文件上传检测<br>内容过滤<br>可信验证  | 文件类型检测<br>内容安全策略<br>数字签名 |

# 第七章 数据完整性

数据完整性要求确保重要数据在传输和存储过程中不被篡改或破坏。

## 7.1 传输完整性

### 安全要求

- 应采用校验技术或密码技术保证重要数据在传输过程中的完整性
- 包括但不限于鉴别数据、重要业务数据、重要审计数据、重要配置数据、重要视频数据和重要个人信息等

### 设计要点

| **数据类型** | **保护措施**           | **技术实现**           |
| ------------ | ---------------------- | ---------------------- |
| 鉴别数据     | 传输加密<br>完整性校验 | TLS/SSL<br>HMAC-SHA256 |
| 业务数据     | 数字签名<br>消息认证码 | RSA签名<br>AES-GCM     |
| 配置数据     | 哈希校验<br>版本控制   | SHA-256<br>Git版本管理 |

## 7.2 存储完整性

### 安全要求

- 应采用校验技术或密码技术保证重要数据在存储过程中的完整性

### 设计要点

- 重要数据存储时计算哈希值，读取时校验
- 数据库关键字段增加校验字段（MAC值）
- 定期进行数据完整性审计
- 采用RAID、副本等技术防止存储介质故障导致的数据损坏

# 第八章 数据保密性

数据保密性要求确保重要数据在传输和存储过程中不被未授权访问和泄露。

## 8.1 传输保密性

### 安全要求

- 应采用密码技术保证重要数据在传输过程中的保密性
- 包括但不限于鉴别数据、重要业务数据和重要个人信息等

### 设计要点

| **保护措施** | **具体要求**                           | **技术实现**               |
| ------------ | -------------------------------------- | -------------------------- |
| 传输加密     | 全程加密<br>TLS 1.2+<br>禁用弱加密套件 | HTTPS<br>SSH<br>IPSec VPN  |
| API通信      | 接口加密<br>Token鉴权<br>请求签名      | AES加密<br>JWT<br>HMAC签名 |
| 敏感数据     | 字段级加密<br>脱敏传输                 | AES-256<br>数据脱敏组件    |

## 8.2 存储保密性

### 安全要求

- 应采用密码技术保证重要数据在存储过程中的保密性

### 设计要点

- 敏感数据加密存储（密码、身份证号、手机号等）
- 采用国密算法（SM2/SM3/SM4）或国际算法（AES-256）
- 密钥分级管理，使用硬件加密机或KMS管理主密钥
- 数据库透明加密（TDE）保护静态数据
- 数据展示时进行脱敏处理（如身份证号显示前6后4）

# 第九章 备份和恢复

备份和恢复要求确保系统能够在发生故障或灾难时快速恢复数据和业务服务。

## 9.1 本地备份与恢复

### 安全要求

- 应提供重要数据的本地数据备份与恢复功能

### 设计要点

| **备份策略** | **具体要求**               | **实现方式**         |
| ------------ | -------------------------- | -------------------- |
| 全量备份     | 每周一次<br>保留4周        | 定时任务<br>备份脚本 |
| 增量备份     | 每日一次<br>保留30天       | binlog<br>差异备份   |
| 恢复演练     | 每季度演练<br>验证可恢复性 | 恢复SOP<br>演练记录  |

## 9.2 异地备份

### 安全要求

- 应提供异地实时备份功能，利用通信网络将重要数据实时备份至备份场地

### 设计要点

- 建立异地备份中心，与主中心距离≥100公里
- 采用同步或异步复制技术实现数据实时/准实时备份
- 备份链路采用加密传输，保障数据传输安全
- 定期验证备份数据的完整性和可恢复性

## 9.3 高可用性

### 安全要求

- 应提供重要数据处理系统的热冗余，保证系统的高可用性

### 设计要点

- 核心系统采用双机热备或集群部署
- 数据库采用主从复制或分布式架构
- 应用层实现无状态设计，支持水平扩展
- 部署负载均衡，实现故障自动切换
- 明确RTO（恢复时间目标）和RPO（恢复点目标）

# 第十章 剩余信息保护

剩余信息保护要求确保系统释放或重新分配存储空间前，将残留的敏感数据完全清除。

## 10.1 鉴别信息保护

### 安全要求

- 应保证鉴别信息所在的存储空间被释放或重新分配前得到完全清除

### 设计要点

- 用户退出/注销后立即清除Session和Token
- 密码字段在内存中使用后立即覆写
- 缓存中的鉴别信息设置合理的过期时间
- 浏览器端禁止保存密码（autocomplete=off）

## 10.2 敏感数据保护

### 安全要求

- 应保证存有敏感数据的存储空间被释放或重新分配前得到完全清除

### 设计要点

- 删除数据时采用安全删除（覆写而非仅标记删除）
- 数据库表空间回收前进行数据擦除
- 文件删除后清空相关缓存
- 日志中避免记录敏感信息，必要时进行脱敏

# 第十一章 个人信息保护

个人信息保护要求系统遵循合法、正当、必要的原则，严格保护用户个人信息安全。

## 11.1 个人信息采集与保存

### 安全要求

- 应仅采集和保存业务必需的用户个人信息

### 设计要点

| **设计项** | **具体要求**                                           | **实现方式**                                 |
| ---------- | ------------------------------------------------------ | -------------------------------------------- |
| 最小采集   | 仅采集业务必需字段<br>明确告知采集目的<br>获取用户同意 | 字段必要性审核<br>隐私政策弹窗<br>授权确认   |
| 存储限制   | 仅保存必要期限<br>到期自动清理<br>支持用户注销         | 数据生命周期管理<br>定时清理任务<br>注销功能 |
| 用户权利   | 查询权<br>更正权<br>删除权                             | 个人信息页面<br>信息修改功能<br>账号注销功能 |

## 11.2 个人信息使用保护

### 安全要求

- 应禁止未授权访问和非法使用用户个人信息

### 设计要点

- 建立个人信息访问审批制度
- 实施数据分级分类管理
